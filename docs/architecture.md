## 一、需求分析

### 1.1 产品定位
**秒记宝宝** 是一款面向新手父母的极简育儿记录小程序，核心解决单手抱娃碎片化时间下快速记录宝宝作息的痛点。

**核心价值**：
- 极致的打开速度（首屏 < 300ms）
- 单手拇指可达的操作区域
- 断网可用、网络恢复自动同步
- 智能作息预测辅助决策

### 1.2 用户画像
| 角色 | 场景 | 核心诉求 |
|------|------|----------|
| 新手妈妈 | 单手抱娃、夜间喂奶 | 快速记录、无需切页 |
| 新手爸爸 | 接班照看、查看状态 | 了解宝宝上次作息时间 |
| 祖辈 | 协助看护、远程关注 | 只读查看、无需操作 |

### 1.3 核心功能矩阵

| 功能 | 优先级 | 复杂度 | 依赖 |
|------|--------|--------|------|
| 极简打卡（首页） | P0 | 低 | 云数据库 |
| 时光轴回顾 | P0 | 中 | 云数据库 |
| 智能预测算法 | P1 | 中 | 历史数据 |
| 成长档案 + 曲线 | P1 | 高 | Canvas、WHO数据 |
| 离线缓存与同步 | P0 | 中 | Storage、网络监听 |
| 每日小结卡片 | P2 | 高 | Canvas、小程序码 |
| 家庭共享与权限 | P2 | 中 | 云函数、邀请机制 |

## 三、数据模型设计

### 3.1 集合结构

#### `records` - 作息记录集合
```json
{
  "_id": "auto_generated",
  "babyId": "cloud_001",
  "recordType": "feed",        // feed | diaper | sleep
  "timestamp": 1694567890000,  // 毫秒时间戳
  "duration": 20,              // 仅 sleep，分钟
  "amount": 120,               // 仅 feed，毫升
  "note": "",
  "userId": "openid_xxx",
  "createdAt": "ISO Date"
}
```
**索引建议**：`babyId + timestamp` 复合索引（倒序）

#### `growth_data` - 成长数据集合
```json
{
  "_id": "auto",
  "babyId": "cloud_001",
  "height": 70.5,              // cm
  "weight": 8.2,               // kg
  "headCircumference": 43.5,   // cm 头围
  "measureDate": "2026-08-17",
  "userId": "openid_xxx",
  "createdAt": "ISO Date"
}
```

#### `family_members` - 家庭成员集合
```json
{
  "_id": "auto",
  "babyId": "cloud_001",
  "openid": "openid_xxx",
  "role": "parent",            // parent | grandparent
  "invitedBy": "openid_yyy",
  "joinedAt": "ISO Date"
}
```

#### `babies` - 宝宝档案集合
```json
{
  "_id": "cloud_001",
  "name": "小花生",
  "gender": "M",               // M | F
  "birthDate": "2026-01-15",
  "avatarUrl": "",
  "ownerOpenid": "openid_xxx",
  "createdAt": "ISO Date"
}
```

#### `invitations` - 邀请令牌集合
```json
{
  "_id": "auto",
  "token": "ABC123",
  "babyId": "cloud_001",
  "inviterOpenid": "openid_xxx",
  "inviteeName": "奶奶",
  "role": "grandparent",
  "status": "pending",         // pending | accepted | expired
  "expireAt": "ISO Date (+24h)",
  "createdAt": "ISO Date"
}
```

### 3.2 权限模型

| 角色 | 记录读写 | 成长数据 | 家庭管理 |
|------|----------|----------|----------|
| 父母 (parent) | ✅ 增删查 | ✅ 增删查 | ✅ 邀请/移除 |
| 祖辈 (grandparent) | 🔍 仅查 | 🔍 仅查 | ❌ |

## 四、性能优化策略

### 4.1 首屏 < 300ms 实现方案

```
小程序冷启动流程
├── 1. 框架初始化（~80ms，不可控）
├── 2. app.js onLaunch
│   ├── wx.cloud.init（异步非阻塞）
│   ├── 从 Storage 同步恢复缓存（~5ms）
│   └── 注册网络监听
├── 3. 首页 onLoad / onShow
│   ├── 立即用本地缓存渲染 UI（~50ms）
│   └── 异步发起云端请求（不阻塞渲染）
└── 4. 云端数据返回后局部 setData 更新
```

**关键策略**：
1. **本地优先渲染**：首页 `onShow` 立即从 `Storage` 读取最近记录时间，无需等待网络
2. **最小化 setData**：每次只更新变化字段，避免全量更新
3. **按需加载**：时光轴/成长档案/分享卡片均为 tab 或跳转页，不阻塞首页
4. **启用 lazyCodeLoading**：`app.json` 中配置 `lazyCodeLoading: "requiredComponents"`

### 4.2 离线策略

```
用户点击记录按钮
├── 1. 立即写入 Storage（同步，~2ms）
├── 2. 更新 UI 显示"已记录"
├── 3. 检查网络状态
│   ├── 在线 → 调用云函数写入
│   └── 离线 → 加入 pendingSync 队列
└── 4. 网络恢复时 onNetworkStatusChange 自动触发同步
```

### 4.3 包体积控制

| 分类 | 预估体积 | 策略 |
|------|----------|------|
| 主包代码 | ~400KB | 无第三方依赖 |
| 组件 | ~80KB | 3 个轻量自封装组件 |
| WXSS | ~20KB | 使用 CSS 变量复用 |
| 图片 | ~100KB | tabBar 图标使用小尺寸 PNG |
| **合计** | **~600KB** | 远低于 2MB 限制 |

## 五、页面结构详解

### 5.1 首页 `pages/index`
- 顶部：宝宝头像 + 日期
- 预测区：三条智能预测文案
- 主操作区：三个大圆角按钮（喂奶/换尿布/睡觉）
- 底部：操作提示文案

### 5.2 时光轴 `pages/timeline`
- 顶部：日期 + 当日小结统计
- 列表：倒序展示当天记录，左滑显示删除
- 底部：生成分享卡片入口

### 5.3 成长档案 `pages/growth`
- 顶部：宝宝基本信息卡
- 中部：Canvas 绘制的生长曲线（叠加 WHO 标准）
- 下部：历史测量记录列表
- 浮动按钮：新增测量数据表单

### 5.4 分享卡片 `pages/share`
- Canvas 绘制 750x1334 分享图
- 包含：当日喂奶/换尿布/睡眠统计 + 小程序码
- 支持：保存到相册、分享给好友

## 六、智能预测算法

### 6.1 算法流程

```
输入：最近 7 天的作息记录
处理：
  1. 按类型过滤（feed/diaper/sleep）
  2. 按时间正序排序
  3. 计算相邻记录的时间间隔
  4. 过滤异常间隔（> 8 小时视为漏记）
  5. 取平均值（舍入到分钟）
  6. 结合"距上次"时间生成预测文案
输出：每类一条预测文案
```

### 6.2 预测文案规则

| 剩余时间 | 文案示例 |
|----------|----------|
| 已超时 | "已超过通常间隔，请留意宝宝状态" |
| < 30 分钟 | "预计 25 分钟内" |
| 30-60 分钟 | "预计约 1 小时内" |
| > 1 小时 | "预计约 2 小时后" |
| 数据不足 | "记录几天后即可生成预测" |

## 七、家庭共享机制

### 7.1 邀请流程

```
发起人（父母）
├── 调用 inviteFamily 云函数
├── 生成 6 位随机 token（24h 有效）
├── 返回小程序路径 ?invite=TOKEN
├── 发送给被邀请者
│
被邀请者
├── 点击链接打开小程序
├── onLoad 解析 invite 参数
├── 调用 acceptInvite 云函数
├── 写入 family_members（角色由邀请人指定）
└── 关联到同一 babyId
```

### 7.2 安全策略
- 仅 `parent` 角色可发起邀请
- token 24 小时过期
- 同一 openid 不可重复加入同一宝宝家庭
- 所有写操作均在云函数侧校验权限
