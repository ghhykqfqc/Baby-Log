# 贝贝log — 登录合规整改说明（先体验、后授权）

> 审核驳回原因：一进入小程序就强制弹窗要求授权手机号/头像/昵称，拦截浏览体验。
> 本整改严格落实微信官方「先体验、后授权」登录规范，同时保证数据不丢失、功能完整。

---

## 一、整改核心思路

```
进入小程序 → 直接打开首页（游客模式，展示宝宝记录 UI、喂奶/换尿布入口）
    ↓ 无任何授权弹窗（wx.login 静默生成匿名 openid，不弹框）
用户点击「记录喂奶」等核心功能
    ├─ 本地可暂存 → 轻提示「已记录 · 登录后自动同步云端」
    ├─ 或弹出登录面板（半屏弹层，非全屏遮挡）
    │    ├─ 「微信一键登录（授权手机号）」
    │    └─ 「暂不登录 / 稍后再说」
    ↓ 登录成功 → 统合游客期间本地数据到云端（openid 前后一致，天然同主）
```

---

## 二、涉及文件与改动

### 1. 新增：登录引导面板组件
- `miniprogram/components/login-panel/`（4 文件）
  - 半屏底部弹层，z-index ≥ 10000（盖过自定义 tabBar）
  - 官方推荐 `button open-type="getPhoneNumber"` 获取手机号
  - 附带「暂不登录，先逛逛」入口 → 游客继续浏览，绝不强制

### 2. 核心控制层
- `miniprogram/utils/auth.js`（新增）
  - `ensureLogin(page, {onSuccess, onGuestClose})` 关键操作拦截入口
  - `notifyLoginSuccess(user)` 登录成功后合并游客数据并放行排队中的操作
- `miniprogram/app.js`
  - `requireLogin()` 不再跳转登录页，仅轻提示（无强制）
  - 新增 `mergeGuestDataAfterLogin()`：游客期本地记录/成长/相册 → 自动同步云端
  - `logout()` 改为回游客模式（保留本地数据，不再 reLaunch 登录页）

### 3. 各页面改造（去掉强制登录 + 关键操作引导）

| 页面 | 改动 |
|------|------|
| 首页 index | onShow 不再强制登录；记录/换尿布/睡眠直接游客可记（轻提示）；新建/加入宝宝、编辑宝宝、分享入口 → 登录面板（可跳过）；顶部头像区游客显示「游客 · 登录享永久保存」 |
| 时光轴 timeline | onShow 开放；「生成分享卡片」→ 登录面板（可跳过）；canvas 与面板共存处理 |
| 成长 growth | onShow 开放；「+ 记录成长」→ 登录面板；保存失败/游客 → 本地暂存，登录后合并 |
| 日程 schedule | onShow 开放；「+ 添加日程」→ 登录面板；游客失败 → 本地暂存 |
| 宝宝资料 profile | onLoad 不再强制登录；保存（新建/编辑）→ 登录面板（可跳过放行） |
| 历史 history | onShow 不再强制登录 |
| 时光记录列表 timeline-records | onShow 不再强制登录；删除本地/云端记录游客可操作 |
| 登录页 login | 从「强制入口」改为「可跳过」：一键登录（getPhoneNumber）+「暂不登录，先逛逛」 |

### 4. 登录语义（用户头像/昵称不再必填）

- 登录按钮使用 `open-type=getPhoneNumber`（微信官方推荐，不再强制填写昵称头像）
- 手机号授权被拒绝时 → 自动降级为匿名 openid 登录（流程不中断）
- `cloudfunctions/userLogin/index.js`：支持 `phoneCode` 换取手机号；无昵称/头像时用默认值

### 5. 审核相关修正
- `app.json`：移除 `requiredPrivateInfos: ["getLocation"]` 与 `permission.scope.userLocation`（代码中未使用定位，消除审核对「未声明用途即弹授权」的质疑）
- 启动页默认 `pages/index/index`（首位），无任何授权弹窗
- 游客期间的数据（云端 + 本地）在登录后自动合并，用户侧无感

## 三、审核合规自检清单

| 审核关注点 | 现状 |
|-----------|------|
| 一进小程序是否强制弹授权 | ❌ 已移除，直接进首页游客模式 |
| 是否强制登录才能使用核心功能 | ❌ 记录/浏览/切换/编辑全开放，仅保存强数据时引导 |
| 登录面板是否全屏遮挡 | ✅ 半屏弹层，可「暂不登录」关闭继续使用 |
| 是否使用官方推荐组件 | ✅ button open-type=getPhoneNumber / chooseAvatar |
| 游客数据是否丢失 | ✅ 本地记录 → 登录合并云端（openid 不变） |
| 是否还有「未登录先跳登录页」路径 | ❌ 已全部移除（login 页仅作可选入口） |

## 四、部署要点

1. 重新上传全部修改的小程序代码；
2. 云函数 `userLogin` 需重新部署（新增 phoneCode 处理）；
3. 若 `getPhoneNumber` 在开发者工具/体验版不可用（基础库 < 2.21.2），组件与登录页已有降级逻辑（自动静默 openid 登录），不影响审核体验；
4. 提交审核时可在「整改说明」中注明：
   - 小程序支持游客模式，核心功能无需登录即可体验；
   - 登录为可选操作，通过系统按钮（getPhoneNumber）触发，不拦截浏览。

## 五、体验流视图

```text
游客首次启动
   └─ 首页（天气、相册占位、喂奶/尿布/睡眠卡、预测）
        ├─ 点“记录喂奶” → 直接记录 + toast「已记录 · 登录后自动同步」
        ├─ 点「宝宝」面板 → 新建/加入（登录面板可跳过）
        └─ 点顶部头像区 → 宝宝面板 → 「登录以永久保存」→ 登录面板
              ├─ 微信一键登录（getPhoneNumber）→ 云端合并 → toast「登录成功」
              └─ 暂不登录 → 返回继续浏览
```

---

## 五、数据合并说明（关键）

- 游客期 openid 由 `getOpenId` 云函数静默产生（wx.login 匿名）；
- 登录后的 openid 与游客期**完全相同**，因此：
  - 游客期写入云端「默认宝宝」的记录、日程、成长数据 → 登录后天然同主，无需搬运；
  - 游客期「本地暂存」的记录（pendingSync / todayRecords local_ 前缀 / growthData 本地项 / 相册本地路径）→ 登录成功后由 `mergeGuestDataAfterLogin` 自动补齐上传；
- 家庭成员模式（宝宝多成员）不受影响：登录仅「用户的资料与身份」完整化。
