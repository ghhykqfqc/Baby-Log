一、项目概述

1.1 产品定位

「宝宝日志log」是一款面向新手父母的科学育娃微信小程序。它围绕"喂奶、换尿布、睡觉"三件日常高频琐事打造一键打卡体验，配合智能作息预测、时光轴回顾、成长曲线、家庭共享、天气皮肤与一键分享卡片，帮助家庭用最少的操作成本科学记录宝宝的完整成长数据，让每一位照看者都能轻松接力、随时掌握宝宝状态。

1.2 产品概况

项目内容
产品名称宝宝日志log（宝宝成长记录微信小程序）
运行平台微信小程序（基础库 ≥ 3.5.0），iOS / Android 双端适配
后端平台微信云开发 CloudBase（云函数 + 云数据库 + 云存储，免运维、免鉴权配置自建）
技术形态微信原生小程序（WXML / WXSS / JavaScript），无第三方框架、无第三方 UI/图表库
项目规模9 个页面、3 个公共组件、24 个云函数、6 类业务数据模型，主包体积约 600KB
当前阶段V1.0 已完备核心链路，V1.2 功能（日程、多宝宝、历史页）完成；迭代路线图持续更新

1.3 设计理念

  • 科学高效：核心操作一键直达、不切页、可单手完成；冷启动首屏使用本地缓存渲染，目标 <300ms。
  • 离线可用：断网照常记录，网络恢复自动补传，不丢失任何一次数据。
  • 家人协作：以宝宝为共享单元，父母 / 祖辈分级权限，全员共同记录、共同查看。
  • 健康温度：采用奶咖色系视觉规范，温暖、柔和、不打扰，适合深夜喂奶场景。

三、小程序功能简介

3.1 功能架构总览

小程序采用"4 个 Tab 主页面 + 5 个功能子页面"的轻量结构，顶部无冗余入口，只保留高频行为：

模块页面能力说明
记录（首页）pages/index天气动态皮肤、宝宝资料条、智能作息预测、相册轮播、三大一键记录按钮、离线待同步队列提示
时光pages/timeline + pages/timeline-records当日摘要（喂奶 / 尿布 / 睡眠三栏）、24 小时三泳道时间分布图、"预计下次"预测卡、按日期分组分页的记录列表、长按删除
成长pages/growth + pages/history焦点数据卡（身高 / 体重 / 年龄）、Canvas 生长曲线（叠加 WHO 标准曲线）、历史记录分页浏览与删除
日程pages/schedule日历视图 + 事项管理（疫苗 / 生日 / 预约 / 兴趣班 / 购物 / 礼物 / 红包 / 自定义）、类别色点标记、未来事项倒计时
共享（资料）pages/profile宝宝头像裁剪上传、多宝宝档案管理切换、宝宝 ID + 密码邀请家人、宝宝信息完整编辑
分享pages/shareCanvas 绘制 750×1334 每日小结分享卡片，内含当日统计、宝宝头像与小程序码，一键保存 / 转发
登录pages/login微信授权登录、家庭邀请接受入口（?invite=TOKEN）

3.2 核心功能清单

  • 一键打卡：喂奶（可带量 / 自定义）、换尿布（小便 / 大便 / 拉稀）、睡觉（带时长分钟），触感反馈 + 即时 Toast，保存不切页；
  • 离线可用：点击瞬间落本地，离线写入待同步队列，网络恢复自动补传（onNetworkStatusChange 驱动）；
  • 智能预测：基于近 7 天同类型记录的相邻间隔均值（过滤 >8 小时异常间隔，兼容二条边界）推"预计下次"时间与倒计时，数据不足时兜底显示；
  • 时光轴：三泳道 × 24h 横轴可视化时间分布图，Canvas 2D 绘制，含 tooltip 交互；
  • 成长曲线：身高 / 体重随时间曲线，叠加 WHO 国际标准发育曲线作对照参考；
  • 日程日历：按月切换的自绘日历，事项按类别上色，未来事项有倒计时提醒；
  • 家庭共享：发起人生成 6 位邀请码（24 小时内有效），受邀人凭邀请码接受邀请后关联到同一宝宝；父母与祖辈分角色权限；
  • 多宝宝：一个家庭可管理多个宝宝档案，一键切换；
  • 天气沉浸皮肤：IP 定位（免授权）+ Open-Meteo 公开天气，五套皮肤（晴 / 阴 / 雨 / 雪 / 风），雨天带 Canvas 雨滴 + 足底涟漪动画；
  • 每日分享卡：自动汇总当日数据生成分享卡片，内置小程序码，便于家庭群与朋友圈传播。

五、解决的实际问题

5.1 痛点 → 方案对照

育儿场景真实痛点本小程序的解决方案
记不住、懒得记：新生父母手忙脚乱，传统记账 app 步骤多、需要切页填写，坚持不下来 三个一键打卡按钮 + 本地即时响应（<50ms），操作路径 1 点击 ≈ 1 秒完成，不切页、不强弹窗
交接信息断裂：夫妻 / 跨代看护（口头传达），轮流带宝宝容易遗忘"上次喂奶几点" 首页"上次 X 时间" + "预计下次"常驻卡片，任何人打开即获取最新状态；家庭共享全员可见
不会判断"正常"：宝宝食欲 / 睡眠节律紊乱，父母不确定是否要干涉 基于自身记录自动学习平均间隔并主动预测提醒，异常间隔过滤（>8 小时）避免误读
成长是否达标：不会看懂生长曲线，担心矮 / 偏瘦 / 过快 本地绘制生长曲线 + 叠加 WHO 国际标准，父母肉眼比对
断网 / 弱网场景多：楼道、地库、乡下信号差窗口，记录流失 本地优先存储 + pendingSync 待同步队列，网络恢复自动补传，数据零丢失
跨家庭成员协作难 宝宝 ID + 6 位邀请码即入共享，parent / grandparent 两种角色，爸妈可写、祖辈可看
家长平时忘记关键节点：疫苗接种日、体检预约、兴趣班 日程日历 8 类 + 自定义提醒，提前在日历上落点，未来事项倒计时
分享缺乏沉淀：晒娃只发照片，没有"数据感"的成长回看 每日小结卡片自动汇总（喂奶次数 / 睡觉时长 / 尿布次数），图文 + 小程序码一键转发

5.2 实际价值小结

  • 将"记录"从负担变为习惯：操作成本从分钟级降至 1 秒；
  • 用数据把家庭照护连接起来，避免"信息在中转中丢失"，守护宝宝喂养与睡眠节律；
  • 为医疗场景提供趋势依据：儿保医生问诊时可直接展示半年的身高体重曲线；
  • 离线优先保障了弱网环境（乡村常驻长辈）的完整使用体验。

6.2 技术选型与理由

层级选型理由
前端框架微信原生小程序零编译损耗、启动最快；免框架升级带来的兼容风险
UI / 图表完全自研（WXSS + Canvas 2D）生长曲线、时间分布图、分享卡片全部原生绘制，无第三方依赖，包体可控、风格统一
后端微信云开发 CloudBase免运维 / 免服务器，天然鉴权，微信生态内闭环
数据库云数据库 NoSQLschema-less，适合记录流数据，配合复合索引（babyId + 时间戳）
缓存 / 离线wx.Storage + 待同步队列同步 API 首屏即出；网络监听事件自动同步

6.3 前端关键技术实现

  • 离联网优先架构：所有写操作先写本地（同步，几毫秒）→ 更新 UI → 根据网络状态决定立即上云或入队；'network status' 变化自动补传失败重试；云环境（cloud.init / 基础库不支持）降级为离线模式，绝不崩溃；
  • 首屏性能：app.json 开启 lazyCodeLoading "requiredComponents"；首页 onShow 直接读取本地缓存渲染，异步请求回来后再局部 setData（最小化更新）；
  • Canvas 自绘三件套：时间分布图（三泳道 × 24h）+ 生长曲线（坐标绘制 / 虚线 / 阴影参考带）+ 分享卡片（750×1334 设计稿坐标等比缩放），统一 canvas.requestAnimationFrame / 绘制缩放方案；
  • 自定义 tabBar（z-index 1000 原生层）与弹层安全层级管理（全屏蒙层 z-index ≥ 10000），全面屏使用 env(safe-area-inset-bottom) 适配，避开 tabBar 遮挡；
  • 设计令牌：全局 CSS 变量（--primary #D4B896 等），圆角梯度 12/24/40/60rpx，样式隔离、主题可扩展。

6.4 后端关键技术实现

  • 24 个云函数微服务化：按业务拆（addRecord / getRecords / … / getWeather / getMiniProgramCode），单函数单一职责，参数白名单校验（如 addSchedule 的类别白名单），写操作全部在服务端（云函数侧）完成鉴权，不信任客户端；
  • 集合自愈机制：云函数内嵌 safeDb / ensureCollections / isCollectionMissing 工具，检测到集合缺失时自动创建，有效规避常见"-502005"数据库异常，提升 demo 与正式部署的稳定性；
  • 数据建模：6 个集合 — records（type / subType / duration / recordTime + index）、growth_data（height / weight / measureDate / monthAge）、babies（avatar / albumPhotos ≤9 张）、family_members（role：parent / grandparent）、invitations（token / status / expireAt 24h）、schedules；
  • 家庭与安全：6 位邀请码 + 24 小时有效 + 一人不可重复加入，先验家人关系再记账，防止越权访问其它家庭数据；
  • 双环境自动切换：按小程序运行版本（develop / trial → DEV_ENV，release → PROD_ENV）自动选择云环境，云函数统一 cloud.DYNAMIC_CURRENT_ENV，发版零配置；
  • 天气数据通道：云函数侧 ipwho.is / ipapi.co 定位 → Open-Meteo 实时天气（免费无 Key），全链路失败兜底返回晴，前端 30 分钟缓存，杜绝白屏。

6.5 部署与发布

微信开发者工具一键"上传并部署"云函数（云端安装依赖）→ 控制台建集合 + 索引 → 真机适配（全面屏、弱网、断网恢复）→ 提审自查清单（隐私、授权说明、内容安全、无诱导分享）。项目已按该流程完成线上线下联调，README 提供一键部署指引。

七、小程序创新点

7.1 极致轻量的"一键打卡"交互模型

核心记录行为被压缩为"一屏、一按、一秒"：首页即操作台，三大圆角按钮拇指全覆盖，点击立即 Toast 反馈、绝不跳页。这一设计把育儿记录变成能长期坚持的习惯，而归因于"愿意记"的前提——成本足够低。

7.2 离线优先 + 待同步队列的韧性架构

所有记录先写本地再上云，断网期间数据零丢失，恢复后自动补全；云环境不可用自动降级为纯本地模式（devMode），前端永不因为后端异常而崩溃。在弱网 / 医院室内 / 乡下等育儿高频场景中提供"跟没有断电一样的流水账体验"。

7.3 自研自适应作息预测算法（含异常过滤与边界回退）

不靠外部 ML 服务，纯本地 + 云端双端实现：取近 7 天同类记录间隔平均，过滤 >8 小时疑似断记数据，两笔记录边界回退保证不误报"数据不足"，并区分"今天 / 明天 / 时:分"与倒计时 / 超时状态文案，让预测既准又温和。（见 utils/predict.js 及云函数 getPrediction）

7.4 原生 Canvas 全自绘 · 零图表/绘图库依赖

生长曲线、24h 时间分布图、750×1334 分享卡片全部是团队手写 Canvas 2D 绘制（含坐标系、scale 缩放、阴影专带、小程序码合成），不引入 ECharts / F2 / html2canvas 等任何第三方图表或渲染库，包体更小（约 600KB）、视觉与品牌严格一致。

7.5 沉浸式天气皮肤 + 程序动画

通过云函数集成 IP 定位与 Open-Meteo（免 Key 免授权），把首页变成随天气变化的"心情页"：晴 / 阴 / 雨 / 雪 / 风 五套皮肤，其中雨天由 Canvas 自绘雨滴 + 落地涟漪动画（requestAnimationFrame 驱动、弹层共存时按 wx:if 卸载重绘策略）实现，一带而完整的"动效系统"自研闭环。

7.6 双角色家庭共享与邀请安全机制

以 babyId 为共享单元，parent / grandparent 双角色权限隔离；6 位邀请码 24h 过期、防重复绑定，全部写操作服务端校验，第一次在个人级记录应用里落地了"爸爸可以记、奶奶只看"的家庭协作模型。

7.7 云函数"集合自愈"机制

针对云开发冷启动环境未建集合导致的经典错误（-502005），团队在官方模式之上封装了 safeDb 巡检：每次调用检测集合存在性并自动创建，部署即用、无运维负累，显著提升稳定性和体验版接入成功率——这是文档中服务端工程化的务实创新。

7.8 免 Key 免费天气方案

天气能力不依赖任何付费 API Key：云函数以 IP 定位（双服务故障转移）+ Open-Meteo 开放接口完成，全程无用户授权、无域名白名单配置，成本趋近于零且开箱即用，契合个人作品与小型团队的开源心态。

7.9 设计系统驱动（奶咖色令牌 + 程序化图标）

全项目不由 CSS 变量统一管理配色、圆角、间距；tabBar 四枚图标由 Python 脚本按设计令牌程序化生成 PNG，保证在任何分辨率下锐利一致，实现"设计即代码"。
